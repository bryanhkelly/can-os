# Design for the entire operation

Every workflow must communicate the next meaningful outcome, not just the next form.

- Explain what is required when an action is blocked.
- Prevent duplicate commands while processing.
- Preserve edits on failure. Distinguish command failure from refresh failure after a successful write.
- Show completion only after authoritative confirmation.
- Separate configuration, authorization, publication, delivery, attendance and measured outcomes.
- Preserve context and explain unavailable or partial data.

## Real command recovery pattern

The Mutation feedback family uses the application's actual mutation runner with controlled local fixtures. The interactive stories assert that a failed read after a successful command is recovered with a read-only retry, and that a failed command preserves the input. Use FormActions with a blocked reason when a form's owning workflow knows why saving is disabled.
