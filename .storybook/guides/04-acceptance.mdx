# Acceptance is evidence, not inventory

| Gate | Command or artifact |
| --- | --- |
| Local catalog | `npm run storybook` |
| Built index validation | `npm run storybook:inventory` |
| Independent browser acceptance | `npm run test:storybook:browser` |
| Static build | `npm run build-storybook` |
| Interaction and accessibility | `npm run test:storybook` |
| Route and layout coverage | `node scripts/check-v61-experience-coverage.mjs` |
| Complete declaration gate | Same command with `--strict` |
| Reviewed visual evidence | Existing V6.1 evidence manifest and Chromatic acceptance |

Accessibility checks are errors by default. Any exception must be narrowly scoped and documented. Automated checks supplement, not replace, keyboard and assistive-technology review.

The route registry starts with candidate layout assignments. Do not mark a route verified until its real rendering, authorizations and acceptance evidence have been checked.

Storybook build or CI failure is not a passing gate. Missing runner logs or absent visual credentials are blockers, not grounds for auto-approval.

The browser matrix exercises six named device and theme combinations, checks rendered overflow, unexpected network access and runtime exceptions, and verifies keyboard focus in the representative launch journey. It is not an authenticated application journey.

## Visual modes

Use named Chromatic Modes exclusively. The default width modes are 390px, 768px, 1024px and 1440px. Existing theme-specific modes remain available. Do not mix the retired viewport-array parameter with Modes. Initial migration or theme changes may require independent baseline review. Never automatically approve visual changes.

## Independent browser coverage

The six-case critical matrix covers the launch journey, milestone states and print reporting. The twelve registered layout reference stories are also exercised in compact and desktop projects. Browser tests validate the real generated index, visible canvas, page overflow and unexpected network or runtime errors. They do not grant visual approval or verify live production workflows.

## Run without GitHub Actions

Run `npm ci`, then `npm run storybook:doctor` to inspect local prerequisites without disclosing credentials. Install Chromium using `npx playwright install chromium` and run `npm run verify:storybook`. For browser compatibility, install Firefox and WebKit using `npx playwright install firefox webkit` and run `npm run test:storybook:cross-browser` after building. The static acceptance server binds only to loopback, serves existing build files only and rejects application RPC and writes. No production environment is needed.

The optional browser projects extend critical and registered-layout smoke cases; they do not automatically expand paid visual snapshots. Chromatic is still independently reviewed.

## Isolated fixtures and typography

Storybook uses local copies of the approved V6.1 typefaces, with pinned upstream blob identities and OFL licenses. `npm run check:storybook:fonts` verifies byte integrity. Browser acceptance requires the local fonts to load and no longer permits third-party font calls.

The Storybook and Vitest bundlers reject runtime imports of production routes, database and server modules, and RPC facades without explicit fixture aliases. A failed isolation check identifies the offending module; fix the adapter boundary rather than bypassing the gate. The static acceptance server restricts connections, form submissions, fonts, and media with a content security policy. This is a development fixture boundary, not a production access-control system.

## Catalog governance

Run `npm run check:storybook:catalog` before review. All story families must use the numbered catalog taxonomy. Duplicate titles, duplicate metadata IDs and removed migrated exports fail the source contract. The built-index contract independently checks the generated catalog.

## Portable release receipt and private review package

From a clean checkout, install dependencies with `npm ci` and Chromium with `npx playwright install chromium`. Run `npm run storybook:acceptance`. Each stage records its local log, the exact Git commit and the tested static output digest in `acceptance-artifacts/storybook-release/receipt.json`. The runner does not forward application environment variables or provider keys. Failed or incomplete acceptance cannot prepare a private preview package.

After a passing receipt, `npm run storybook:prepare-private-preview` prepares only the checked static files, excludes separate source maps and adds preview security headers. This is not visual approval or production authorization, and does not deploy anything. Use a separate private hosting project, verify anonymous access to the manager, iframe and static assets is denied, and keep receipts and logs outside the published directory. Never use the production application project.

## Browser evidence for review

The static browser matrix now retains a rendered PNG for each successful exercised canvas as well as failure traces and screenshots. The HTML report links the review images; the JSON report supports machine inspection. These images must still be reviewed by a human against the design contract and visual baseline. They do not replace authenticated route acceptance. The receipt links to run-specific stage logs, so an incomplete new run cannot silently borrow an older run's logs.
