# Becomuna Design System V6.1

The living reference for the application, public experiences and institutional partners. V6.1 remains the production design authority. This library documents reusable implementations, not a second component system.

## Find the right starting point

| Area | What it is for |
| --- | --- |
| Foundations and primitives | Tokens, typography, accessible controls, surfaces |
| Components | Reusable, domain-neutral interface elements |
| Application patterns | Saving, evidence, decisions, progress, sharing |
| Page layouts | The twelve governed page archetypes |
| Interaction states | Missing information, failure, pending, success and recovery |
| Persona experiences | Role-specific composition and priorities |
| Feature workspaces | Actual application feature components with synthetic data |
| Public experiences | Branded, unauthenticated presentation |
| User journeys | Multi-step, interactive examples |
| Engineering and acceptance | Contribution, coverage and testing contracts |

Core foundations, primitives and layout families now use the numbered navigation taxonomy with explicit legacy metadata IDs. Remaining legacy families are migrated incrementally. The built-index check guards existing story URLs.

## Start with reuse

Look for an existing component or composition before building a new one. Choose a layout, identify the interaction states, use the canonical primitives and add a story with the actual component. Only add a new primitive when the design owner approves a genuinely new contract.

## What Storybook proves

Stories document rendering and controlled interactions. They do not certify identity, persistence, publication, delivery, consent, or server-side authorization. All example people, organizations, outcomes and commands are synthetic.

Use the theme and viewport toolbars to inspect platform light, platform dark and validated institutional branding. Device presets range from 320px to 1920px.

Open [Coverage explorer](?path=/story/12-engineering-and-acceptance-coverage-explorer--route-inventory) to search route files, filter by proposed layout or review status, and see the registered story references. The explorer uses the repository registry directly, not manually entered totals.
