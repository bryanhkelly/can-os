# Site Intelligence and Gloo AI Studio

## Contract v1 / prompt site-editorial-v1

The canonical Site Content Brief is assembled on demand. No new lifecycle workspace or duplicate CMS. The external projection is distinct from the internal brief. Website and Introduce both use the same provider and review controls.

Required input: schemaVersion, promptVersion, target, site (name, organization, brand name/direction, identity, hosting, environment), planning (programs, audiences, experiences labeled proposed), taskContext (null or outreach selections), preferences. Missing source facts are null/empty; never guessed. Optional story, leadership biographies, current copy and public reference URLs are off by default, each independently selected and gated by saved content reuse permission. References are supplied only as reference text; no autonomous web crawling or profile scraping. No raw Site UUID, EIN, private contact lists, credentials or evidence records are sent. Free-form inputs must be inspected for private details by an authorized operator.

Output: a single strict JSON object {schemaVersion:1,target:"website"|"outreach",website:object|null,outreach:object|null,reviewNotes:string[]}. Website fields: heroHeadline (120), welcomeMessage (240), localDescription (1400), schoolVision (1200), communityOutreach (1200). Outreach: headline (160), message (1600), callToAction (100). Only the requested block is populated. Output links, protected claims, oversized fields, unknown keys and invalid JSON are rejected. Operator confirms accuracy; no automatic publication. Actual link destinations and templates remain owned by existing services.

Gloo integration: fixed POST https://platform.ai.gloo.com/ai/v2/guarded/responses, Bearer API key, configured model, bounded input/output, no redirect, no provider fallback. Reference: https://github.com/GlooDeveloper/gloo-ai-docs-cookbook/tree/main/responses/typescript . Set GLOO_API_KEY as a server secret and GLOO_MODEL to a model available in the organization's Gloo Studio account. Confirm provider privacy/data-processing terms and usage limits before enabling with real Site content. Configure both deployment targets as appropriate, not feature flags. Never include credentials in client bundles or source. No provider request is issued by reviewing the input.

Flow: authorized editor saves reuse consent in private website draft, prepares the exact JSON, explicitly authorizes transfer to Gloo, generates a draft, reviews each output, applies selected fields, then uses existing versioned save/approval. Digest binds input to Site and source revisions. Source and actor rechecked after generation. Audit records request and completed response metadata and digests, not raw prompts or content; this is generation provenance, not a durable link from every applied field to its generation. Existing artifacts retain normal content/brand versioning.

Acceptance: run typecheck and build, the contract and provider-mock tests, existing Site Brief tests, website/outreach browser workflows; test unauthorized users, revoked consent, cross-Site grants, stale input, wrong model response, provider timeouts/guard blocks, field selection, version conflicts and private draft first-save path. Confirm production provider configuration and test against synthetic data before permitting real inputs. Existing release security gates remain outstanding. No production credentials, external generation or deployment executed in this change.
