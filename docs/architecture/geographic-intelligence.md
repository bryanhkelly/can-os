# Geographic Intelligence (release-11232026)

One address, derived geography; no new mandatory setup fields. Existing geographic_areas and Site geographic_area_id remain the canonical regulatory/catalog state link. Geography membership never grants reporting or operating authority. Canonical codes are source-qualified; CBSA crosses state lines, so do not force all reporting into a single tree. The new versioned memberships and relationships are separate from permission-based bottom-up reporting tags.

## Processing and privacy
Migration 0121 queues physical Sites on insert/address change and backfills existing Sites, invalidates the current observation immediately on change, and leaves previous observations available for as-of reporting. No synthetic demo address is sent to Census; unsupported countries, virtual/mobile Sites, incomplete addresses and PO boxes do not manufacture a market. The initial worker processes at most one Site and one community profile per scheduled invocation; retries are bounded and leased, and address changes fence obsolete completions. Source boundary version is preserved. No live requests on reporting or website reads. ACS 2024 five-year data is explicit, with estimates, denominators and margins of error stored centrally per geography/year. CENSUS_DATA_API_KEY is the only new credential, necessary for data queries (not geocoding). A missing key leaves profile work pending. Do not log addresses, keys or provider URLs. Census matched coordinates can be interpolated rather than parcel-verified. Market unknown is distinct from nonmetro and rural.

## Shared reporting
Use readAuthorizedSiteGeography or the internal scoped reader after an existing whole-Site authorization gate. For network aggregates, filter the already-authorized atomic activity/participant facts by geography as of the activity date; deduplicate using the existing canonical Person and event identities. Never sum overlapping partner aggregates. Do not infer participant residence or program service geography from a delivery address. The entity geography contract defines roles for other entity kinds, but their assignment and authorization adapters are not implemented by this initial migration. Private Person address geocoding is not enabled. No regulatory decisions may derive solely from these observations.

## Acceptance before deployment
Validate migration with production-shaped schema and restricted-role tests (including security-definer trigger owner privileges); run migration journal, typecheck, unit tests, browser and scheduler acceptance. Confirm Census live layer names and IDs, market and nonmarket behavior, API key and ACS query/variable responses, cross-state CBSA, missing and ambiguous geocodes, address change during a lease, historical as-of, synthetic isolation and reporting authorization. No live database migration or API request is implied by this commit. Region/urban/school/district facts only where the provider supplies validated IDs. USDA rural classifications, international providers, time-zone derivation, geographic visualization, cross-entity persistence, broad market dashboard and demographic expansion remain follow-on work.

Migration 0122 accounts for verified Launch Studio physical-address revisions and delivery metadata when site_kind is unset, and explicitly excludes synthetic records and digital-only Sites. Boundary lookups pin ACS2024_Current; profile and geography years align. Site Intelligence includes validated aggregate ACS profiles and labels in the existing optional editorial input (never street addresses or coordinates). Gloo instructions distinguish aggregate community estimates from participants and require attribution when stating estimates.

## Universal declared entity geography and governed report filters
Migration 0123 introduces one typed, FK-backed assignment table; Site delivery remains derived. Partner coverage refers to an Organization, and learning activity initially refers to canonical noncredit participation events. Organizational/program/Offering/campaign/partner/funding declarations require independently verified platform administration; activity delivery requires the existing authorized provider scope; Person residence and activity participation are optional, coarse, explicitly self-consented and self-only. Withdrawal deletes optional private geography; nonprivate declarations close the active historical interval. No personal geography enters report options, Gloo or public output. No generic tenant or geography-based authority is granted. Tenant editing UX and additional legacy activity adapters remain deferred.

The shared V6.1 ReportGeographyFilter uses canonical Field and Select with Storybook interaction and responsive states. Current delivery evidence filters authorized releases by the current Site observation. Historical pilot outcomes match at registration time, retaining full-cohort feedback reconciliation before selecting and deduplicating outcomes. Unknown is not outside market. Source data remains subject to existing disclosure rules and report bounds. No client-supplied area broadens authorization. Reports without a geography selection retain prior behavior.

### Provider verification and reporting reuse
The Census geocoder vintage catalog confirms ACS2024_Current = 424, benchmark 4. Census TIGERweb ACS2024 publishes metro layer 93 and micro layer 91 (GEOID, NAME). The provider now checks these pinned identifiers and resolves omitted market layers via point-in-polygon queries. Explicit empty responses establish nonmarket status, not an error or omitted layer. Live public landmark acceptance is available via `node --import tsx scripts/acceptance/check-live-census-geography.mjs`; without the Census Data API key it returns a nonzero partial-acceptance status. No live tenant addresses or keys are logged. The same private geography options hook is reused across the report center and enrollment evidence panel. Historical observations are not retroactively backfilled to registration dates before the first verified resolution.
