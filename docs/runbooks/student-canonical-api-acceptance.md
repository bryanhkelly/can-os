# Student canonical API acceptance

Run `npm run qa:pilot -- student` from a clean exact-revision checkout using the existing dedicated QA branch and ignored `.env.pilot-qa`. Set `CAN_STUDENT_QA_JSON` to a JSON object with two reviewed synthetic students, one legacy school student and one canonical-only student at distinct Sites. Each student supplies email (.test), grantId, personId, organizationId, siteId, canonicalOnly and the exact active enrollments (classId, classEnrollmentId, courseAttemptId). No session cookies or fixed credentials. No new production endpoints. No SQL writes.

For positive mutation coverage, optionally supply write: {attestation:"fresh-synthetic-fixture",personId,classEnrollmentId,lessonId,assignmentId} using a fresh unpublished-response fixture with a not-started homework assignment and incomplete lesson. This tests normal APIs, own versus foreign enrollment authorization, replay behavior and read-after-write. Repeated positive runs require a fresh fixture; absence of write is read/denial coverage only.

The runner checks normal one-time email access, grant selection, Person identity, native Class discovery, resume, lessons, homework and cross-Site denial. Separate pilot acceptance owns adult registration, pairing, attendance and formative activities. The school projection is optional, not an authorization source for canonical coursework. Remaining historical school records stay behind their own scoped adapters. This suite does not yet assert native draft saving, released grades, course completion, credential issuance, withdrawal, guardian consent, support, or scheduling. No full lifecycle claim until the exact release is built and all required runtime acceptance passes.
