# Native Deployment Site placement

The ordinary application API `placeNativeDeploymentSite` binds the Site in a current, independently reviewed and executed Blueprint to its canonical deployment. Only an exact authorized Site Admin or Registrar with existing Blueprint execution capability may act. It does not create a Site, Operation, operator relationship, readiness decision, approval, or operational permission. A new placement is limited to planning or review; a matching existing instruction placement can be acknowledged on retry. Authorization is checked again inside the transaction. A placement, audit and event are committed atomically.

The isolated standard API acceptance stage `place-deployment` takes operator, foreign, deploymentId and siteId. It checks explicit cross-organization denial, exact retry behavior, a single persisted instruction placement and unchanged adoption/deployment state. Run it after `execute-blueprint` and before independent readiness and adoption review. Use the actual returned deployment ID; no SQL seeding of business records. This is not a replacement for the outstanding operational authorization and activation APIs. Runtime execution is not yet verified.
