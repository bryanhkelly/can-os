# Deployment readiness API

The ordinary recordNativeDeploymentReadiness command records append-only operating, registration or delivery readiness against an exact independently reviewed Blueprint deployment and current authorized Site. The existing owner access administration workflow can appoint a separate organization-wide deployment_readiness_reviewer on a verified account. This does not grant Blueprint adoption, operation activation or learner access. Direct ordinary CAN sessions only; private credentials and owner act-as do not authorize review. The command requires current Organization-owned evidence verified by another Person and bounded by its validity period. The review cites the latest superseded decision or null for the first one. Exact retry IDs are checked against persisted terms. The API never creates evidence, permissions, or positive findings automatically.

Currently restricted to pre-adoption deployments with a single planned Site. Broader deployments need separately governed review of their complete scope. The independently authorized adoption reviewer must differ from the readiness reviewer. Operational authority and activation remain separate. Public reviewer authentication for legacy Blueprint adoption is not yet migrated. Source tests and live acceptance still need execution.

The governed acceptance stage `review-deployment-readiness` takes reviewer, operator, foreign, deploymentId, reviewId, reviewKind, evidenceVersionId, expiresAt and supersedesId. Run separately for all three readiness categories after placement, with actual independent reviewed evidence. It checks explicit denial of author and foreign organization, exact retry, conflicting retry and persisted reviewer/evidence, and does not activate the deployment.
