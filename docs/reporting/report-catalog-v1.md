# Report catalog and comparison foundation

The catalog contains stable versioned discovery metadata; it is not an access grant, database configuration store or arbitrary query engine. The existing /reports route hosts provider delivery and registration-cohort outcomes. Class, Site, Go Link and infrastructure reports retain their respective resource-specific workflows. Network impact is explicitly unavailable until canonical principal, host metric grants and disclosure governance are independently established.

The private query hook includes current workspace identity and the exact report/resource/date selection, never uses previous data placeholders, hides data during refetch/error and disables reads when session verification is missing. Server functions remain authoritative. Provider summary consumers share the identical query key and reader. The provider release chart follows the existing Site selection without recalculating unique people or sums.

The shared UTC date control uses completed days and exclusive end. Class and noncredit outcomes reuse it. Class comparison is between equal-duration independently fetched cohorts, only with matching contract versions. It is not an as-of reconstruction, and missing counts produce no delta. Existing private CSV export remains unchanged except that unavailable data is not exposed while refreshing.

Required release evidence: full npm install, typecheck, lint, unit and Storybook execution, Cloudflare build, authenticated provider and Class navigation, scope switch, denied endpoint, missing metrics and date-range browser tests. No database migrations or new access grants.

Pilot acceptance requires newly created registrations to be visible immediately. The pilot default therefore remains the server's rolling 90-day window through the current time, with optional closed UTC date selection. Class defaults likewise retain today's partial UTC day. Equal-period Class comparisons are enabled only for complete UTC windows; a partial current day never masquerades as a comparable period. Date filters and comparison code distinguish these time bases explicitly.

## Provider filter context v1

The Report Center owns a verified-session-keyed provider filter context; independent workspaces have scoped local fallback state. Site and geography selections persist across the two provider reports, as does the learning outcome date selection. Current delivery geography and historical registration geography are explicitly labeled and independently revalidated. Selecting geography does not clear a Site or silently widen scope. All/none are explicit; an unavailable selection blocks results until verified or cleared. Options are bounded, private, no-store, source-owned and never authorization. The delivery reader remains identical across its consumers; Site slicing uses its already-authorized aggregate and release rows. Outcomes send an optional UUID Site selector to the existing canonical provider reader; it independently checks current permitted Sites and narrows final facts only after full authorized cohort evidence/feedback attribution. Distinct people are recomputed from selected facts, not summed across Sites. A lifetime delivery reader never accepts a historical date filter. No new network grants, generic SQL execution, Program/Offering filter adapters, persisted preferences or publication authority.
